This release fixes issues found while reviewing MacFanPro and its ThermalForge upstream. Based on ThermalForge 0.2.3.

## What's fixed

- **Launch at Login:** a failed change rolls back once, avoiding repeated registration calls; users can retry.
- **Foreground fan control:** `watch` and calibration use the installed daemon's ownership rules and protection. Concurrent foreground sessions and conflicting manual holds are rejected.
- **M4 temperature protection:** efficiency-core sensors now participate in both the app and daemon safety checks. The Smart curve and existing 95°C / 90°C safety thresholds are unchanged.
- **Calibration cancellation:** Ctrl-C and SIGTERM stop and join load workers before cleanup. Sensor or cleanup failures are reported, and cancelled calibration results are not saved.
- **Logging:** malformed, nonpositive or overflowing durations are rejected; recordings started with sudo belong to the invoking user.
- **Calibration files:** user-file operations drop supplementary root groups as well as the effective user/group. Removal failures are reported instead of claiming success.

Before running `sudo macfanpro watch`, quit the menu bar app. Its polling interval is now limited to 0.01–5 seconds. Calibration closes the invoking user's app and reopens it afterwards. Finish any existing manual CLI hold before starting either command.

## 中文说明

本版修复对照 ThermalForge 上游与 MacFanPro 代码审计中发现的问题。

### 修复内容

- **登录启动开关**：设置失败时只回滚一次，避免反复注册，可再次尝试。
- **前台风扇控制**：`watch` 和校准通过已安装后台服务的控制权规则及保护机制执行；拒绝并行前台任务与已有命令行手动控制的冲突。
- **M4 温度保护**：效率核心传感器纳入应用和后台服务的保护温度；Smart 曲线、95°C 触发与 90°C 回落阈值不变。
- **校准中断**：Ctrl-C、SIGTERM 会停止并等待负载线程退出，再清理控制；传感器或清理失败会报错，中断结果不保存为校准。
- **日志采集**：拒绝错误、非正数及溢出时长；sudo 启动的记录也归调用用户所有。
- **校准文件**：用户文件操作同时切换有效用户、主组及附加组，避免继承 root 的组权限；删除失败会明确报错。

运行 `sudo macfanpro watch` 前须退出菜单栏应用，采样间隔为 0.01–5 秒。校准会关闭调用用户的应用，结束后重新打开。两者启动前须结束已有命令行手动控制。
