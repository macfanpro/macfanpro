[中文说明](#中文说明)

Reduce repetitive diagnostics, improve fan-control handback and low-temperature stability, and check for updates every six hours. This summary combines the changes in 0.2.3.67 and 0.2.3.68. Based on ThermalForge 0.2.3.

## Changes

### 0.2.3.68

- Shorten automatic update checks to six hours. Failed checks still retry after about one hour, and manual checks remain available.
- Keep the previously scheduled check when upgrading; the six-hour interval applies after the next successful automatic or manual check. Sleeping Macs check when the app resumes and the scheduled time has arrived.

### Included from 0.2.3.67

- Rate-limit ordinary temperature-anomaly reports and collapse consecutive identical process snapshots.
- On quit, stop accepting monitor writes, complete pending commands off-main, and release app-owned control last. CLI holds remain protected.
- Keep a fan's previous target when its automatic-mode write is rejected; preserve firmware readback and recovery.
- Require five sampled cold seconds before normal Smart/curve release, avoiding immediate release after a brief temperature dip. Explicit Default/Silent and safety/failure recovery remain immediate.
- Update displayed readings once per second; profile and control-state changes still update immediately. Control/safety polling remains at 100ms.
- Skip absent temperature probes after complete firmware discovery, rediscover after wake, and add reported sensor keys only on M6 hardware.

## Verification and limitations

Local Debug and Release tests passed (182 tests each), together with installer, disconnect, mirror and localization-packaging checks. All six downloaded draft assets passed checksum, signature, version, language-resource and old-updater compatibility verification before publication. Assets were built locally from the tag using the release packaging script; the hosted release run was cancelled before any steps ran because no runner was assigned. Independent hosted CI was still queued at publication preparation.

See the [version validation record](https://github.com/macfanpro/macfanpro/blob/main/docs/macfanpro-0.2.3.68-validation.md). Packages use ad-hoc signatures and are not notarized by Apple. No physical fan-control, high-temperature, or sleep/wake acceptance was performed for this update-check scheduling change. M6 fan control and temperature mappings remain unverified on M6 hardware; see the separate [0.2.3.67 validation record](https://github.com/macfanpro/macfanpro/blob/main/docs/macfanpro-0.2.3.67-validation.md) for that version's evidence.

## 中文说明

减少重复诊断日志，改善风扇控制交还及低温稳定性，并将自动检查更新的间隔缩短为 6 小时。此处汇总 0.2.3.67 和 0.2.3.68 两次发布的更新内容。基于 ThermalForge 0.2.3。

### 更新内容

#### 0.2.3.68

- 每 6 小时自动检查一次更新，失败后仍约 1 小时重试；随时可以手动检查。
- 升级时保留之前已安排的下一次检查时间，下一次自动或手动检查成功后采用 6 小时间隔。电脑休眠期间不会专门唤醒检查，应用恢复运行且到期后再检查。

#### 已包含的 0.2.3.67 更新

- 普通温度波动报告增加限频，重复进程历史合并输出。
- 退出应用时先停止接收监控指令，在后台完成已接收的指令，最后释放应用持有的风扇控制；保留终端控制权。
- 自动模式写入被拒绝时保留风扇之前的目标转速，继续使用固件读回确认和恢复机制。
- Smart 和普通曲线在连续采样低温五秒后才正常释放，避免短暂降温导致立即交还；用户明确选择 Default/Silent、高温保护恢复及失败清理仍立即处理。
- 读数每秒刷新，模式和控制状态变化立即显示；温控及安全检查保持 100ms 周期。
- 完整枚举固件键后跳过不存在的温度键，唤醒后重新发现，并仅在 M6 上补充报告的温度键。
