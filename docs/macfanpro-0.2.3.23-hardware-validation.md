# MacFanPro 0.2.3.23 实机补充验收

2026-09-27，在已发布并安装的 0.2.3.23 上补做高温保护和真实睡眠唤醒。设备为 M4 Max MacBook Pro（Mac16,5），macOS 27.0 / 26A428，接通电源。生产代码、风扇曲线、保护阈值和校准数据未修改。

此前发行验收只有自动化、包和安装证据，缺少这两项硬件检查。本记录补充实际执行结果；不将模拟测试或普通启动视为实机睡眠唤醒。

## 高温保护与降温释放

菜单栏 App 保持用户原有 Smart 模式。独立 CPU 负载从 4 个进程增加至 8 个，约每 0.5 秒通过 CLI 的只读 SMC 连接采样风扇与温度，同时读取 daemon 控制权和系统热压力。首次采到保护温度达到 95°C 后立即停止负载，继续记录降温过程。

| 检查 | 实测结果 |
| --- | --- |
| 保护采样峰值 | 96.6°C；使用生产代码的 `TC` / `Tp` / `TG` / `Tg` 安全传感器集合。此值不同于菜单栏 CPU 核心温度；本轮核心温度峰值为 87.9°C。 |
| 保护触发 | App 日志记录 `Override triggered: 96.6°C`。首次高温采样后约 0.58 秒的采样中，daemon hold 为 App 的 `max`，两只风扇均为手动模式，目标均为 5777 RPM。该时间是采样观测差。 |
| 实际转速 | 记录到的峰值分别为 5440、5417 RPM；停载后温度迅速下降，目标随降温下调，未持续维持最高转速。 |
| 降温恢复 | 保护峰值采样后约 4.4 秒，49.8°C 时控制权变为 `none`，风扇回到自动控制；随后连续 10 次采样确认低于 50°C、无 hold、无手动模式。 |
| 服务与系统状态 | 49 次采样无错误；daemon 状态查询最大耗时约 13.8 ms；系统热压力始终为 `nominal`。完整负载及降温记录约 25.1 秒。 |

负载在 8 进程阶段达到停止条件，因此没有继续 16 进程或 CPU+GPU 阶段。以上证明一次实际高温触发及降温释放，不是长时间压力稳定性结论。

## 睡眠、完整唤醒与 CLI 设定恢复

执行前检测到一个远程控制软件的防睡眠锁，向用户说明远程连接会中断，并取得自动睡眠及定时唤醒许可。测试先设置两只风扇为 3000 RPM，确认 CLI hold；添加带本次唯一 owner 的一次性唤醒事件，并在 60 秒后用短时用户活动声明恢复完整唤醒。没有关闭远程软件或修改常驻节能设置。

最终有效测试的系统事件时间为北京时间：

| 时间 | 证据 |
| --- | --- |
| 17:33:21 | `pmset` 日志确认 `Software Sleep`，进入实际睡眠。 |
| 17:33:52 | 系统因网络/SMC 活动进入 DarkWake；此时不判定完整唤醒。 |
| 17:34:16 | 到预定唤醒时刻，系统日志确认 `DarkWake to FullWake`、HID Activity。 |
| 17:34:23 | root daemon 的风扇日志再次写入两只风扇 3000 RPM；SMC 采样确认恢复手动模式及目标 3000。 |
| 17:34:49 | 两只风扇实际转速分别为 3000、3000 RPM，控制权仍为 CLI 的 `set 3000`。 |
| 17:34:52–17:34:58 | 释放测试 hold；最终为无 hold、两只风扇系统控制。 |

App 和 daemon 的原进程保持运行，版本仍为 0.2.3.23。Smart、跟随系统语言、摄氏度设置均保留；校准文件 SHA-256 前后同为 `ae3f21af50d214851e2fdf6cee86258870b081ce8f5d3ce09e7ef6f676aa6c91`。本次负载、临时唤醒辅助程序、日志监听均已退出，自有计划唤醒事件无残留。

唤醒确认采用系统电源日志、daemon 的实际风扇写入日志和 SMC 读回。统一日志未捕获 `re-applied after wake` 文本，因此不把这条文本作为已取得的证据。

## 测试工具的两处更正

1. 第一次负载采样通过 daemon 的 `status` verb，使用 3 秒超时；该请求和风扇写入共享硬件锁，而 M4 首次接管预算最长 20 秒。因此采样中断后立即停止负载。App 随后正常完成接管与自动释放，进程未重启。有效重跑改用 CLI 的独立只读 SMC 连接监控温度，daemon `state` 单独检查响应。没有通过延长盲区继续加热。
2. 第一次睡眠脚本误将 DarkWake 当作完整唤醒，并提前结束，取消了尚未触发的唤醒事件。该轮作废；恢复完整唤醒后，修正为保留事件至预定时间，并留足完整唤醒后的固件接管时间，再完成上表中的有效测试。

这些更正针对本次验收脚本；本轮没有修改或重新安装产品代码。
